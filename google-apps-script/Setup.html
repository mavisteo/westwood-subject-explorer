WESTWOOD · ONE-TIME STAFF SETUP

Connect your school content.

The hosted planner is a working student preview using the prepared content snapshot. This installation creates the live Google Sheets database and the Google-authenticated staff dashboard. It is designed for colleagues in the same Google Workspace school domain.

Download installation package ↓

1. Create the Apps Script project

Unzip the package. In your school Google account, open Google Apps Script ↗ and create a new project. Copy Code.gs into the script file. Create HTML files named Student, Admin, Styles and Seed, and copy the corresponding file contents from the package.

2. Initialise the database

Select setup in the function menu and run it. Authorise the script using your school account. Open the execution log for the new Google Sheet URL. Setup will not overwrite an existing installation. It creates Subjects, Subject_Combinations, Combination_Subjects, Subject_Eligibility, Admins and Change_Log sheets, and makes your Google email the first Admin.

3. Deploy the student page

Choose Deploy → New deployment → Web app. Choose Execute as: Me. For a student page that requires no login, choose Who has access: Anyone, if school policy permits. Deploy and copy the resulting /exec URL. Students receive only the public subject information; staff email allowlists and change logs are excluded.

If your domain does not permit anonymous web apps, students will need their school Google accounts. The student login-free requirement cannot be met through that deployment while this domain restriction applies.

4. Deploy staff access

Create a second deployment of the same project. Choose Execute as: Me and restrict access to users in your school Workspace domain. Add ?mode=admin to this deployment’s /exec URL. Staff identity is checked on the server using their active Google account and the Admins allowlist. Blank or unauthorised identities are denied.

In Project settings → Script properties, set ADMIN_URL to this full staff URL, including ?mode=admin. The student page’s Staff access button will use it. Personal Gmail accounts and users in other domains are not supported as staff by this deployment model.

5. Add colleagues and complete the briefs

Open the staff dashboard using your allowlisted school account. In Admins, add colleagues’ school Google emails with role Admin or Editor and active: true. Admins manage access and view the log; Editors edit subject briefs, combination rules and informational eligibility wording. You do not need to share the database workbook with Editors.

Use the subject dropdown to locate briefs marked requires completion. Economics, Computing and Elements of Business Skills have no supplied descriptor. General descriptors adapted across levels should be checked by the respective Westwood subject teams before school rollout.

6. Embed in Google Sites

In Google Sites, use Insert → Embed → By URL with the student /exec URL. Give the frame sufficient height and test on phone and desktop. Staff content edits update the student page on the next load or refresh. Routine content updates do not require code changes or a new deployment.

Check before rollout

Verify an anonymous student view, a listed Editor account and an unlisted school account. Confirm a saved descriptor appears after student refresh, that an Editor cannot manage Admins, and that the change log records updates. Google Apps Script quotas and your school domain settings apply.
